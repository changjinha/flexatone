# 00. 공통 개념 — 모든 스튜디오가 공유하는 뼈대

스튜디오는 10개지만 밑바닥 구조는 하나입니다. 이 문서를 먼저 읽으면 나머지 튜토리얼에서 반복되는 용어(정규화 곡선, 로그 음고, 베이킹, 1/√N, 출력 단계)를 매번 다시 설명할 필요가 없습니다.

---

## 1. 모든 스튜디오는 결국 "보이스"를 만든다

```
[스튜디오 고유의 생성 규칙]      ← 스튜디오마다 다름 (확률, 물리, 카오스, 프랙탈 …)
        │
        ▼
  음고 궤적 p(t)  +  진폭 a(t)  (+ 스튜디오에 따라 팬, 밝기)
        │
        ▼
  오실레이터 (5파형 가산 음색)  →  보이스 합산 (1/√N 보정)  →  출력 단계 (페이더·리미터)  →  스피커 / WAV
```

- **보이스(Voice)** = 시간에 따라 음고와 음량이 변하는 소리 줄기 하나. Glissando Studio의 기본 단위입니다.
- 다른 스튜디오는 "보이스를 어떻게 만들 것인가"에 대한 서로 다른 수학적 답입니다.
- 대부분의 스튜디오에 있는 **글리산도 보이스로 베이킹(Bake to Glissando Voices)** 버튼은 결과를 일반 Glissando 보이스(최대 64개)로 바꿔 줍니다. 이때 **보이스에 없는 정보(팬, 필터 밝기, 위상 등)는 사라집니다.** 각 튜토리얼 끝에 "베이킹 시 손실" 항목이 있습니다.

---

## 2. 정규화 곡선 y(t) ∈ [0, 1]

대부분의 모양은 **0→1 구간에서 0→1로 가는 함수**로 표현됩니다.

- 시간도 정규화합니다: `t_norm = (t − 시작) / 길이`.
- 이 y(t)를 **실제 음고 범위**나 **실제 값 범위**로 펼치는 것은 별도 단계입니다: `값 = lo + (hi − lo)·y(t)`.
- 덕분에 같은 곡선 엔진이 음고, 진폭, 템포, 밀도, 속도 등 어디에든 쓰입니다.

**소리 관점:** y(t)의 *모양*이 제스처의 성격(급출발, 감속, 튕김, 계단)을 정하고, lo/hi가 *크기*(몇 옥타브를 움직이는지)를 정합니다.

## 3. 음고 축: 왜 "로그"인가

사람은 주파수의 **비율**을 음정으로 듣습니다(440→880 Hz와 220→440 Hz는 둘 다 한 옥타브).

| 매핑 | 수식 | 들리는 결과 |
|---|---|---|
| 로그 (기본) | `f = F₀·(F₁/F₀)^y` | y가 일정하게 늘면 음정이 일정하게 오름. 직선 = 고른 글리산도 |
| 선형 Hz | `f = F₀ + (F₁ − F₀)·y` | 아래쪽에서 빨리 오르고 위쪽에서 느려지는 것처럼 들림 |
| MIDI ↔ Hz | `f = 440·2^((m − 69)/12)` | MIDI는 이미 로그 축. 1 = 반음 |

피아노롤 화면의 세로축은 MIDI(= 로그 주파수)입니다. 화면에서 직선이면 귀에도 일정한 속도의 글리산도입니다.

## 4. 곡선 엔진 (Curve Engine) — 14가지 모양 함수

Glissando에서 가장 많이 쓰지만, Cloud·Tempo·Space·Chaos 등도 "시간 곡선"을 만들 때 같은 엔진을 씁니다. 자세한 파라미터는 [01_Glissando](01_Glissando.md)를 보세요.

| # | 엔진 | 수학적 정체 | 소리 제스처 |
|---|---|---|---|
| 1 | 조화 S-회전 | 코사인 S커브 + 피벗각 α로 기울인 사인 항 | 부드럽게 출발·도착, α로 중간을 앞/뒤로 몰기 |
| 2 | 도착잠금 감쇠진동 | `1 + A·e^(−kτ)·sin(2πNτ)` (t₀ 이후) | 목표음 도착 후 출렁이며 안착 (비브라토가 잦아드는 느낌) |
| 3 | 탄도형 예비동작 | `t^p − 후퇴 + 오버슈트` | 반대 방향으로 살짝 물러났다가 확 튀어나감 |
| 4 | 미분음 래칫 | `(⌊Nt⌋ + smooth({Nt}))/N` | N단 계단. σ가 작으면 또렷한 음 계단, 크면 미끄러운 계단 |
| 5 | 가변 비브라토 스윕 | 상승 S커브 + 속도가 f₀→f₁로 변하는 사인 | 오르면서 비브라토가 빨라지거나 느려짐 |
| 6 | 중력 탄성 바운스 | `1 − e^(−kt)·|cos(…)|` | 공이 튀듯 목표음에 여러 번 부딪히며 안착 |
| 7 | 3차 베지어 | 제어점 P₁, P₂ | 자유로운 가속/감속 곡선 |
| 8 | 경유 정체 | C² 5차 선반 | 중간 음에서 잠시 머물렀다 다시 이동 |
| 9 | 다항 / 상수 | 라그랑주 보간 | 찍은 점을 모두 지나는 매끄러운 선 |
| 10 | 다중 함수 모핑 | 여러 엔진의 가중 합/곱/차 | 위 제스처들의 합성 |
| 11 | 커스텀 | 편집 가능한 베지어 스플라인 | 손으로 그린 임의 궤적 (베이킹 결과가 주로 이것) |
| 12 | 지수/로그 | `(e^{kt}−1)/(e^k−1)` / 역함수 | 지수: 천천히 출발 후 급상승 / 로그: 급출발 후 천천히 |
| 13 | 삼각·역삼각 | sin, atan 등 구간 정규화 | 진동형 또는 포화형 곡선 |
| 14 | 사용자 수식 | `f(t; a, b …)` | 원하는 수학식 그대로 |

공통 버튼: **시간 반전** `f(1 − t)` (제스처를 거꾸로), **값 반전** `1 − f(t)` (상승 ↔ 하강).

## 5. 음색: 5파형 가산 합성

모든 스튜디오의 오실레이터는 하나의 `PeriodicWave`(배음 64개)를 씁니다.

| 파형 | n번째 배음 진폭 | 소리 |
|---|---|---|
| 사인 | n = 1만 | 맑고 순수. 음고 움직임이 가장 또렷하게 들림 |
| 삼각 | 홀수, 1/n² | 부드럽고 약간 피리 같은 |
| 톱니 | 모든 n, 1/n | 밝고 현악기/금관 같은 |
| 사각 | 홀수, 1/n | 속이 빈 클라리넷 같은 |
| 리치 | `n^−0.75·(1 + 0.35 sin 1.3n)` | 밝고 약간 불규칙한 스펙트럼 |

- **믹스 모드**: 다섯 파형을 비율로 섞음.
- **f(x) 모드**: 한 주기 파형을 수식(또는 다른 보이스의 곡선)으로 정의 → DFT로 배음 계수 `a_k` 계산.

**소리 관점:** 배음이 많을수록 밝고, 동시에 **글리산도가 겹칠 때 거칠기(roughness)도 커집니다.** 보이스가 많은 스튜디오(Cloud, Risset, Wave)는 사인 위주가 깔끔합니다.

## 6. 진폭과 음량 단위

| 단위 | 정의 | 직선 페이드가 어떻게 들리나 |
|---|---|---|
| 진폭 (amp) | 선형 0…1 | 앞부분에서 급격히 커지고 뒤는 거의 안 변하는 것처럼 들림 |
| dB | `A = 10^(dB/20)`, 0…−60 dB | 고르게 들리는 페이드 (DAW 방식) |
| Sone | 지각 음량, `sone ∝ amp^0.602` | 두 배 sone = 두 배로 크게 들림 |

**여러 보이스 합산 (게인 버스):**
- 서로 상관없는 사인을 N개 더하면 파워가 N배 → 진폭은 √N배. 그래서 대부분 스튜디오가 **1/√N**(동일 파워)을 곱합니다. 보이스 수를 늘려도 음량이 폭발하지 않는 이유입니다.
- 모드: `sum`(그냥 합), `equalPower`(1/√N), `soneNormalize`(지각 음량 맞춤).

## 7. 출력 단계 (Loudness Manager) — 모든 스튜디오 공통

| 컨트롤 | 수학 | 소리 |
|---|---|---|
| 페이더 | `A = 10^(dB/20)`, τ = 5–10 ms 평활 | 최종 음량. 평활 덕분에 "지지직" 노이즈 없음 |
| dB 테이퍼 A/B | A: dB 선형 / B: 바닥 15%는 진폭 선형 | B는 바닥에서 소리가 툭 끊기지 않음 |
| 리미터 | 비율 20 컴프레서 + 2배 오버샘플 클램프 | 0 dBFS를 넘지 않음. 너무 세게 걸리면 펌핑 |
| Sone 측정 | 24 Bark 대역 라우드니스 모델 | 실제로 얼마나 크게 들리는지 수치화 |
| Sone 락 | `ΔdB = log10(S_목표/S_측정)/0.023` | 스튜디오·프리셋을 **같은 체감 음량**으로 비교 |

WAV 내보내기도 같은 단계를 거치므로 "들리는 소리 = 파일"입니다.

## 8. 베이킹(Bake)과 캐시 — 왜 재생이 가벼운가

무거운 계산을 하는 스튜디오(Field, Chaos, Space, Fractal, Wave, Cloud, Tempo, Draw)는 공통 원칙을 따릅니다.

1. 파라미터를 **편집할 때 한 번** 시뮬레이션해서 배열로 저장(베이킹).
2. 재생·루프·탐색·WAV는 그 배열만 읽음.
3. 배지의 "베이킹 N회" 숫자는 **모양에 영향을 주는 파라미터를 바꿀 때만** 늘어남. 음색·게인 같은 소리 파라미터는 다시 계산하지 않음.
4. 시드(seed)가 같으면 결과도 항상 같음(결정론적 난수 `mulberry32`).

**실용 팁:** 재생 중 숫자가 늘어나지 않는 게 정상입니다. 편집했는데 소리가 안 바뀌면 배지가 늘었는지 먼저 확인하세요.

## 9. 공통 모듈: 트레몰로

보이스 단위 진폭 LFO입니다. `g = 1 − d·(1 − m(φ))`, `m = (w(φ)+1)/2` — 음량을 **낮추기만** 하므로 클리핑이 없습니다.

- 속도 3–8 Hz: 전형적인 트레몰로. 20 Hz 이상: 거친 윙윙거림(진폭 변조 음색).
- 시작/끝 속도를 다르게 하면 위상을 적분하므로 튀지 않고 아첼/리타.
- 박 동기: `Hz = 박당 주기 × BPM / 60`.
- 위상 동기 "전체 타임라인"이면 겹친 보이스가 함께 맥동합니다.
